# 钉钉配置与联调

本系统使用**企业内部应用机器人＋Stream 模式**。群自定义 Webhook 机器人不能代替完整双向入口。

## 页面中需要填写的配置

| 页面字段 | 来源 | 用途 |
|---|---|---|
| Client ID / AppKey | 应用凭证中的 Client ID / AppKey | 建立 Stream 和获取访问令牌 |
| Client Secret / AppSecret | 应用凭证中的 Client Secret / AppSecret | 应用认证；保存到本机，不回显 |
| Robot Code | 机器人配置中的 Robot Code | 主动向你发送消息 |
| 接收人手机号 | 企业通讯录中登记的中国大陆手机号 | 保存时查询 userid，绑定唯一操作者及消息接收人 |

填写中国大陆 11 位手机号，也支持 `+86` 前缀、空格和短横线。系统调用钉钉“根据手机号查询用户”接口得到 userid；消息发送和指令身份校验仍使用 userid。手机号必须属于当前企业成员。

## 控制台操作

1. 进入钉钉开发者后台，选择自己的企业，创建企业内部应用。
2. 添加机器人能力，设置名称、头像和介绍。
3. 消息接收模式选择 **Stream**，保存配置。
4. 开通接收机器人消息及机器人向企业用户主动发送单聊消息所需的权限。控制台名称可能随版本变化，以 `POST /v1.0/robot/oToMessages/batchSend` 对应权限为准。
5. 开通“根据手机号查询用户”接口对应权限，确认通讯录可见范围包含接收人；设置应用可见范围，包含自己的企业账号，并发布应用版本。
6. 打开工作台“系统设置 → 钉钉消息通道”，填写上述四项配置，点击“保存并连接”。不要把密钥粘贴到聊天。
7. 保存后立即生效，无需重启；在同一页面确认 Stream 已连接。
8. 点击“向我发送测试消息”。收到后回复“项目”，验证上行和下行均成功。

## 保存与修改

配置保存在当前数据目录的 `dingtalk.json`，通过原子替换写入，权限为 0600（仅当前用户可读写），内容未加密。保存时先使用本次填写的应用凭据查询手机号，成功后才写入配置、关闭旧连接、清除缓存令牌并使用新配置连接。认证失败、权限不足、成员不存在或网络异常时保留原有配置和连接。界面只返回密钥是否存在，不返回密钥内容。

旧版仅有 userid 的配置继续有效；下次在页面保存时需补充手机号。手机号和查询得到的 userid 一同保存在本机配置中。

再次修改时 AppSecret 留空保留原值；更换 AppKey 时必须提供新密钥。页面保存的配置在重启后仍生效，并优先于 `.env`。尚未在页面保存时，服务仍使用原有四项 `DINGTALK_*` 环境变量作为初始值。

保存成功只表示配置已持久化；实际连接状态和测试消息结果需要在页面检查。未配置期间积累的通知会在配置后继续发送。

## 实际使用

先在 Web 注册本地仓库。单项目下向机器人直接描述需求即可；多项目使用“新任务 项目ID：需求”。完成后机器人提供任务、分支、SHA 和确认编号。

只有发送 `批准合并 <任务ID> <确认编号>` 或在本机工作台点击确认，才会开始交付。消息中的源码、日志和 AI 输出不会被当作授权。

## 常见阻塞

- **手机号查询失败**：检查手机号是否登记在当前企业、是否开通“根据手机号查询用户”权限及对应通讯录可见范围；页面保留钉钉错误码，但不显示接口原始响应中的敏感内容。
- **未连接**：检查应用凭证、是否开启并发布 Stream 机器人、Mac 是否能访问钉钉服务。
- **能收不能发**：检查 Robot Code、主动单聊权限、应用可见范围和接收人绑定。
- **发出的消息无响应**：确认使用绑定的企业账号；其他发送者的消息会被忽略。
- **电脑睡眠**：恢复联网后 SDK 尝试重连；服务未运行期间无法保证实时接收。

实现依据：已安装的 `dingtalk-stream@2.1.6-beta.1` SDK 的类型及 README；真实企业权限与双向收发仍需完成上述联调后才能确认。

参考：[钉钉 Stream 开发说明](https://opensource.dingtalk.com/developerpedia/docs/explore/tutorials/stream/overview)。

手机号查询接口：[根据手机号查询用户](https://open.dingtalk.com/document/orgapp/query-users-by-phone-number)，`POST /topapi/v2/user/getbymobile`。
